# Locus 0.3.0

## 拒绝一处交错，不再等于拒绝整份文件

`locus span` 读一条 trace 内的包含关系，只要有两个 span 部分重叠而不嵌套，就拒绝整份派生。
在一份真实的二十四小时报告上，这条规则**什么都没返回**：十八万四千个闭合 span 里只有三十九处交错，
全部集中在一个亚秒簇内，却废掉了文件里每一条与之无关的读数。

成因不是任何产品埋点的缺陷。**trace 是语义角色而不是进程**，同一 trace 下的并发工作按构造就会交错，
而并行发出命令的 agent 产生的正是这种形状。派生所需的前提被正常操作违反，因此会反复复发。

拒绝现在**按交错所及的时间定域**。与该窗口相交的每个 span 都记入一条 `tangled` 记录，
带上 trace、窗口、以及窗口内被弃的 declaration；与窗口无交的 span 照常派生。
在同一份报告上，这个尺度的代价是十九万六千个 span 里的三百零二个。

定域**没有比先前宣称更多的东西**，因为包含关系让它闭合：任何包住被弃 span 的 span 都会碰到同一处交错、
被一并弃掉，所以幸存的 span 永远不会去减一个被拒的孩子。要救回交错本身需要记录里并不携带的父指针，
**而猜一个，正是这条派生存在的理由所要拒绝的那种归因**。

## Inspection 能量「时间去哪了」

此前的 mapping 只量编码字节与主导内容前缀，产品能问自己的记录有多大，却问不出时间去了哪里。

第三种 mapping `held-time-nanoseconds` 按 Context 分组报告 held 与 inclusive 时间，
对照产品声明的阈值。**它跑的是 span 那条派生而不是第二条**，所以 mapping 与 `span` 命令
拒绝同样的交错、丢弃同样的 span；inspection 的 summary 现在计入被拒数量，
阈值因此不会被拿去对照一个被悄悄缩短的总量。

分组键取自**进入记录自己的 Context**，绝不从外层帧继承。因此，没有在 source 记录上绑定 role 的产品
只能按 trace 分组 —— 那是关于该产品 Context 的陈述，而不是 mapping 的缺口。

底座未变。没有任何 parent role、生命周期、归因或产品词汇进入 Atom 流；
每个派生量都留在接受面下游、并且 stdin 优先。Plumb lock 推进到 0.20.0。
